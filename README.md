## How to Run Locally

### Prerequisites

- [Node.js](https://nodejs.org/) (v18 or newer recommended)

### Steps

1. Install dependencies (first time only):
   ```bash
   npm install
   ```

2. Start the CSS watcher in the terminal (auto-rebuilds CSS on every save):
   ```bash
   npm run watch
   ```

3. Open a page in the browser — choose one of the options below:

---

### Option A — With Live Server (Recommended)

Live Server auto-refreshes the browser on every file save, so you see changes instantly.

**Install Live Server:**
1. Open VS Code
2. Click the **Extensions** icon in the left sidebar (or press `Ctrl+Shift+X`)
3. Search for **Live Server**
4. Click **Install** on the one by *Ritwick Dey*

**Use it:**
- Right-click any `.html` file in the VS Code file explorer
- Select **"Open with Live Server"**
- The page opens in your browser and refreshes automatically on every save

> Run `npm run watch` and Live Server **at the same time** for the best experience — CSS and HTML changes both reflect instantly.

---

### Option B — Without Live Server

> **Important:** The HTML files use absolute paths (e.g. `/dist/output.css`). Opening files by double-clicking in File Explorer uses the `file://` protocol, which does **not** support absolute paths — the page will load without any styles. You must use a local server.

A lightweight alternative to Live Server is the **VS Code built-in simple browser** or any other local server tool. The recommended approach remains Live Server (Option A).

## How to Build for Production

Always run a build before deploying to generate the latest CSS:

```bash
npm run build
```

This compiles `input.css` into `dist/output.css`. All HTML pages load this file automatically.

## Deploy & Share with Client

You can deploy the site to a live URL to share it for review — no server required, just a free hosting account.

### Option A — Firebase Hosting (already configured)

This project is already set up for Firebase. Just install the CLI and deploy:

```bash
npm install -g firebase-tools   # install once
firebase login                  # log in to your Google account
npm run build                   # generate latest CSS
firebase deploy                 # deploy to live URL
```

The terminal will print a live URL like `https://your-project.web.app` that you can share with the client.

---

### Option B — Netlify (drag & drop, no CLI needed)

Netlify lets you deploy without any setup:

1. Run the build first:
   ```bash
   npm run build
   ```
2. Go to [netlify.com](https://netlify.com) and sign in (free account)
3. Click **"Add new site"** → **"Deploy manually"**
4. Drag and drop the **entire project folder** onto the Netlify drop zone
5. Netlify gives you an instant live URL to share

> Every time you make changes, rebuild with `npm run build` and re-drag the folder to update the deployment.

---

### Option C — Cloudflare Pages

1. Run the build first:
   ```bash
   npm run build
   ```
2. Go to [pages.cloudflare.com](https://pages.cloudflare.com) and sign in (free account)
3. Click **"Create a project"** → **"Direct Upload"**
4. Give your project a name
5. Drag and drop the **entire project folder** onto the upload area
6. Click **"Deploy site"**
7. Cloudflare gives you a URL like `https://your-project.pages.dev`

> To update: go to your project on Cloudflare → **"Create new deployment"** → upload the folder again after rebuilding.

---

### Option D — GitHub Pages

If your project is on GitHub, you can host it for free directly from the repository:

1. Run the build and push all changes to GitHub:
   ```bash
   npm run build
   git add .
   git commit -m "build"
   git push
   ```
2. Go to your repository on [github.com](https://github.com)
3. Click **Settings** → **Pages** (in the left sidebar)
4. Under **"Branch"**, select `main` and folder `/` (root)
5. Click **Save**
6. GitHub gives you a URL like `https://your-username.github.io/your-repo/`

> Every time you push changes to the `main` branch, GitHub Pages updates automatically within a minute.

## How CSS Works in This Project

### The flow

```
You edit  →  input.css  or  HTML files
                  ↓
         npm run watch (running in terminal)
                  ↓
         dist/output.css  (auto-generated)
                  ↓
         Browser reflects the changes
```

There are **two places** where you make styling changes:

1. **Directly in HTML files** — using Tailwind utility classes (e.g. `class="text-lg font-bold bg-primary"`)
2. **In `input.css`** — for custom reusable classes, color tokens, fonts, and breakpoints

Both are picked up automatically by `npm run watch` and compiled into `dist/output.css`.

> **Important:** `npm run watch` must be running in the terminal for any changes to reflect in the browser. Without it, edits to `input.css` will NOT appear — `dist/output.css` only updates when the watcher is active (or when you manually run `npm run build`).

### Never touch `dist/output.css`

This file is auto-generated and overwritten every time you build or save. Any manual edits to it will be lost.

---

### What to edit in `input.css`

`input.css` is organized in sections:

| Section | What it contains |
|---|---|
| `@import` (top) | Google Fonts import |
| `@theme { }` | Design tokens — colors, fonts, breakpoints |
| `@layer base { }` | Global element and reusable class styles |
| Rest of the file | Component-specific classes (buttons, cards, modals, etc.) |

**Change a color globally:**
```css
@theme {
  --color-primary: #191f3a;   /* ← change here */
}
```
Every element using `text-primary`, `bg-primary`, etc. updates automatically after the watcher recompiles.

**Add a new reusable class:**
```css
.my-new-class {
  @apply text-lg font-medium text-primary;
}
```

**Change a font or breakpoint:**
Update the values in `@theme`:
```css
--font-fira: Fira Sans, sans-serif;
--breakpoint-lg: 1024px;
```

## How to Modify HTML Pages

Each `.html` file is a standalone page. All pages follow the same structure:

```html
<head>
  ...
  <link rel="stylesheet" href="/dist/output.css" />  <!-- generated CSS -->
</head>
<body>
  <!-- page content -->
  <script src="/js/common.js"></script>
  <script src="/js/..."></script>  <!-- page-specific JS -->
</body>
```

To add or change content, open the relevant `.html` file and edit it directly.
